The chart path, end to end

How a bar or line chart gets under a FinTell reply, which code owns each piece, and why a chart can never cost the user their answer.

Source ARCHITECTURE-SPINE.md (AD-17 to AD-25) PRD prd-Agentic_BChatbot-2026-11-22 Updated 22 Nov 2026

Five rules to keep in your head

  • AD-17

    One code-only node

    chart_builder runs on every path, between join and response_generator. It makes no LLM, SQL or network calls, so the first streamed token is not delayed.

  • AD-18

    It never touches the fallback

    Any failure becomes chart_error on its own field. The Text Reply is unchanged.

  • AD-20

    The SQL carries the shape

    Fixed column names such as category + spending, or period + balance. They are cached with the SQL, so cold and warm runs agree.

  • AD-21

    The note is code, not prose

    One fixed string per skip reason, added by response_generator only when the user asked for a chart.

  • AD-23

    The UI owns the look

    The backend sends points and labels. The browser picks colours from its own tokens and draws nothing if anything looks wrong.

Where it sits in the graph

Every route converges at join before the reply is written. That is why the chart decision can see every outcome, fallbacks included, and still finish before the reply streams. It also lets the no-chart note go into the reply text.

The contracts between stories

These shapes are fixed so that the people building the prompts, the rules, the trace, the UI and the eval runner can't drift apart.

SQL output columns

label  merchant | category | subcategory | period
value  spending | income | net | balance
opt.   period_start, period_end

period = strftime('%Y' | '%Y-%m' |
                  '%G-W%V' | '%Y-%m-%d')
Owned by the text2sql and sql_correction prompts, together with the constants in chart_rules.

ChartResponse (state)

decision         bar | line | none
skip_reason      SkipReason | None
explicit_request bool
spec             ChartSpec | None

ChartSpec  chart_type, title,
           x_label, y_label,
           points[{label, value}]
Written only by chart_builder. Labels are display-ready and points arrive in plot order.

Trace entry

agent    "chart_builder"
status   ok | skipped | error
details  decision, skip_reason,
         explicit_request,
         note_appended, point_count,
         title
metrics  null
Built by _build_agent_trace. The eval runner reads only this and visualization.chart_type.

Before the demo

  1. Run shift and rebuild transactions.db. The data currently ends on 13 June 2026, so "last month" returns nothing.
  2. After the prompt changes, run DELETE FROM query_cache and delete the Redis qcache:* keys.
  3. Start the app with HISTORY_LOOKBACK_HOURS=0 for evaluation runs, and give every request a fresh session_id.
  4. Run the dataset cold, then warm, then on /process-stream, then with CHART_FAULT_INJECTION=true. Do one more run with CHART_FEATURE_ENABLED=false as the latency baseline. Keep to 18 requests a minute or fewer.

Still to confirm
